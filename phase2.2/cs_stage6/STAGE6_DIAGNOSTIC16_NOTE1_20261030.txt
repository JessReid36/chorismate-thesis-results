Stage 6, DIAGNOSTIC 16, NOTE 1 (30 October 2026).

A record-keeping correction. It changes nothing in DIAGNOSTIC 16's pre-registration, its
criteria, its runs or its result. It is written because the error is in the permanent record and
rewriting the permanent record is not how this project corrects things.


N1.1  WHAT IS WRONG

Commit 3e532b4, of 2026-10-29 15:34:27 +0200, added

   phase2.2/cs_stage6/STAGE6_DIAGNOSTIC16_20261029.txt

and carries this commit message:

   "Stage 6 Diagnostic 15: does the per-site sum bound the whole mixed-sign design?"

That is DIAGNOSTIC 15's commit message. It is byte-identical, subject and body, to commit
3e743ad of 2026-10-29 05:35:28 +0200, which added DIAGNOSTIC 15's pre-registration ten hours
earlier. So `git log` shows two commits announcing Diagnostic 15, and the second of them is
Diagnostic 16's pre-registration.

Cause: the script that made the commit (y27) was derived from the script that made the previous
one (y26) and its commit-message heredoc was not changed.


N1.2  WHAT IS NOT WRONG

The committed FILE is correct and is DIAGNOSTIC 16's pre-registration, unaltered:

   STAGE6_DIAGNOSTIC16_20261029.txt   sha256 4e3547fb34d9bee6da7ac128cc9f42a88567c6ae06882e2b74d1d325480c9de1
   STAGE6_DIAGNOSTIC15_20261029.txt   sha256 4e8b4f88725bb3a275aa1514800e7fda89cccef9332015371fb29caf47e7fc46

Two different files. Commit 3e532b4 added exactly one file and that file's content has never
been modified.

The ordering a pre-registration exists to establish is intact and is demonstrable from the
commit timestamps, which are not affected by the wrong subject line:

   2026-10-29 15:34:27 +0200   3e532b4   DIAGNOSTIC 16's pre-registration committed
   2026-10-29 16:17 (approx)             PBS job 422847 cm_d1416 begins its first run
   2026-10-29 21:19:34 +0200             the last of the 148 runs ends

Its criteria were fixed roughly forty minutes before the first run existed. Nothing about
DIAGNOSTIC 16's result depends on the commit subject.


N1.3  WHAT IS DONE ABOUT IT

Nothing is rewritten. Commit 3e532b4 stands with its wrong subject, and this note is the record
that it is wrong and why. Rewriting a pushed commit to correct a message would alter a history
this project relies on being unaltered, which is a worse fault than the one it fixes.

This file is the entry a reader of `git log` should be sent to on finding two commits that
announce Diagnostic 15.

An audit of every STAGE6_DIAGNOSTIC*.txt file against the subject of the commit that added it
found one other class of mismatch and no other defect: Diagnostics 1 to 9 were all added by
c80a80c, a single commit of 12,383 files whose subject names only the newest work in it. That is
a batch import, not a mislabelled pre-registration, and no note is warranted for it.

From DIAGNOSTIC 17 onward the committing script checks that the commit subject names the
diagnostic whose file it is adding, and stops if it does not.
