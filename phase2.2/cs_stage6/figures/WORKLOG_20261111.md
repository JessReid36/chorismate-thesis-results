## 8. Correction on the PC: the first command block replaced a symlink

- The first block unpacked the bundle with tar straight into ~/Desktop. On the PC the code repository is reached
  through a symlink there. GNU tar replaces a symlink to a directory when it extracts a directory of the same
  name, so the link became a plain folder holding only cs_writeup_check.py, and the validation failed with 72
  failures and 13 of 19 negative tests. The repository behind the link was not touched. Nothing was committed.
- Cause: the rehearsal used plain clones on a simulated Desktop and never a symlinked one. Reproduced afterwards
  with a symlinked clone: the same 72 failures and the same six negative tests silent.
- Repair block: the checker copied into the real repository and compared byte for byte, the stray folder removed
  with rmdir, the link restored, and the validation re-run with its negative tests. This section was appended
  by that block only after the validation passed. Rehearsed against no-hardlinks bare mirrors.
- For later bundles: unpack into a new empty folder and copy from there. Never unpack over a repository.
