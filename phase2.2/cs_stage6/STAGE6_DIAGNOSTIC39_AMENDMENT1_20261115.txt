==============================================================================
STAGE 6, DIAGNOSTIC 39.  AMENDMENT 1
A VALIDITY CHECK ON ROUTE X'S LOWEST ROOT
Written 15 November 2026, before any D39 output had been read.
==============================================================================

A pre-registration is never edited. This amendment sits beside it and adds one reading
and one gate. It changes no run, no input, no method and no existing reading.

WHAT THE PRE-REGISTRATION DID NOT COVER

C39.2 covers route X refusing to run: the auxiliary basis is rejected, X_N fails, the
other two X runs are not attempted and route M stands alone. That is the loud failure.

There is a quiet one it does not cover. IP-EOM-DLPNO-CCSD can run, converge, and report
roots that are not clean one-electron detachments. The ORCA manual prints a diagnostic
for this beside every root:

   "Percentage singles character=     96.89"

A root dominated by single excitations is the one-electron detachment the VDE is defined
as. A root with substantial double-excitation character is a different physical process
wearing the same label, and comparing it to route M's energy difference would be
comparing two different things while reporting them as one.

R39.6 as written would make that comparison without noticing. If route X's lowest root
were a poor one-electron detachment, R39.6 would report a disagreement between the two
CCSD numbers and the pre-registration would have me read that disagreement as evidence
about route M's open-shell reference, which is the opposite of what it would mean.

WHAT IS ADDED

R39.10  For each route X run: the percentage singles character of every root reported,
        with the lowest root's value stated beside the energy it is being used for.

G39.18  The harvest reports R39.10 for every route X run that produced a root. Where the
        lowest root's singles character is below 90 per cent, R39.6's comparison for
        that system is reported with the label NOT A CLEAN ONE-ELECTRON DETACHMENT and
        is not read as evidence about route M's reference. The number is still printed;
        it is not dropped.

WHERE 90 PER CENT COMES FROM, STATED PLAINLY

No committed document in this project sets a threshold for this quantity, and three
searches of the repository for one returned nothing; I could not find one. The ORCA
manual prints the diagnostic without naming a cut-off. So 90 per cent is a convention
adopted here, and the only thing that makes it worth anything is that it is written down
before the outputs were read, so it cannot be chosen afterwards to suit whichever answer
comes out. It is labelled as a convention in the result and not as a literature value.

The manual's own worked example reports 96.89 per cent for a root it treats as a normal
ionisation, which is the single data point available and is well clear of the bar. That
is context, not a source for the number.

WHAT THIS DOES NOT CHANGE

Nothing is re-run and no input is touched. R39.3, the CCSD(T) detachment energy from
route M, does not depend on route X at all and is unaffected by this amendment in every
branch. D39.5 still stands: route X cannot be substituted for route M, and a route X
root that passes this check does not become an independent estimate. The four
contingencies are unchanged.
